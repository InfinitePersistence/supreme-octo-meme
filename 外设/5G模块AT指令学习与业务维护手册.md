# 5G 模块 AT 指令学习与业务维护手册

> 适用范围：Linux/Windows 主机通过 UART 或 USB 串口管理 4G/5G 蜂窝模块；数据链路可以是 PPP、ECM/NCM/RNDIS、QMI 或 MBIM。
>
> 文档版本：v1.0，2026-09-03。

## 1. 维护思路

AT 指令主要操作模块的**控制面**。一条 `AT` 返回 `OK`，只能证明当前串口与 AT 解释器可通信；它不能证明 SIM 正常、已注册网络、已建立数据会话，更不能证明业务服务器可达。

一条完整的 5G 数据业务链路如下：

```text
业务程序
  │
  ├─ DNS / TCP / TLS / 应用协议
  │
主机 IP、路由、防火墙
  │
  ├─ PPP / ECM / NCM / RNDIS / QMI / MBIM
  │
5G 模块 ── AT 控制口
  │
  ├─ PDU Session / PDP Context（APN 或 DNN）
  │
运营商核心网（EPC 或 5GC）
  │
LTE/NR 小区 ── 天线、射频、电源
  │
USIM ── 套餐、开户、鉴权、漫游权限
```

维护时从下往上逐层确认：

1. 模块是否供电并被主机枚举；
2. AT 口是否可通信；
3. SIM 是否就绪；
4. 射频功能是否开启；
5. 是否注册到运营商网络；
6. 是否建立数据上下文或 PDU Session；
7. 主机是否获得地址、路由和 DNS；
8. IP、域名和业务端口是否真正可达。

## 2. AT 通信模型

### 2.1 三个角色

- **TE/DTE**：Terminal Equipment，发送 AT 指令的主机或 MCU。
- **TA/MT/DCE**：模块中的 AT 解释器及移动终端功能。
- **UICC/USIM**：SIM 卡及其鉴权、用户身份和运营商配置。

USB 5G 模块通常枚举出多个端口，例如 AT、Modem、GNSS/NMEA、诊断口和 QMI/MBIM 控制口。端口编号没有跨型号的统一保证，不能因为某台设备上 `/dev/ttyUSB2` 是 AT 口，就在所有设备上写死该编号。

### 2.2 一次 AT 交互包含什么

发送端通常以 `<CR>`（十六进制 `0D`）结束命令：

```text
发送：AT+CPIN?<CR>
接收：<CR><LF>+CPIN: READY<CR><LF><CR><LF>OK<CR><LF>
```

接收内容分为三类：

- **中间响应**：如 `+CPIN: READY`，携带命令查询结果；
- **最终结果码**：如 `OK`、`ERROR`、`+CME ERROR: ...`；
- **URC**：Unsolicited Result Code，模块主动上报的异步事件，如注册状态变化、来短信、掉线或重启完成。

URC 可能插入一条命令的响应中间。因此生产代码不能简单地执行“写一行、读一行”。正确做法是：一个读取者持续接收数据，再把命令响应与 URC 分流。

### 2.3 四种常见扩展指令形式

以 `+CMD` 表示某条扩展指令：

| 形式 | 示例 | 含义 |
|---|---|---|
| 执行 | `AT+CMD` | 执行动作 |
| 读取 | `AT+CMD?` | 读取当前值 |
| 测试 | `AT+CMD=?` | 查询支持的参数范围 |
| 设置 | `AT+CMD=<参数>` | 修改参数 |

看到陌生指令时，优先查该型号和当前固件版本的手册。`=?` 通常是能力查询，但并非所有厂商实现都完全规范。

### 2.4 常见最终结果码

| 结果 | 含义 | 维护动作 |
|---|---|---|
| `OK` | AT 层执行成功 | 继续验证业务状态，不能在这里宣布恢复 |
| `ERROR` | 失败但原因不详细 | 开启详细错误，再核对语法和支持情况 |
| `+CME ERROR: ...` | 设备、SIM 或移动业务错误 | 记录完整错误文本/数字，查对应固件手册 |
| `+CMS ERROR: ...` | 短信业务错误 | 记录完整错误，检查短信配置和网络状态 |
| `NO CARRIER` | 连接结束或数据通道未建立 | 同时查看注册、会话和数据接口状态 |
| `>` | 模块等待正文或数据 | 进入提示符状态，不能当成普通一行响应 |

建议每次会话先执行：

```text
ATE0
AT+CMEE=2
```

- `ATE0` 关闭命令回显，使解析更简单；
- `AT+CMEE=2` 请求详细设备错误文本。少数固件只支持数字错误，应以 `AT+CMEE=?` 的结果为准。

## 3. 建立安全的实验环境

### 3.1 Linux：先识别端口

以下均为只读命令：

```bash
lsusb
dmesg -Tw
ls -l /dev/ttyUSB* /dev/ttyACM* /dev/cdc-wdm* 2>/dev/null
ip -br link
```

确定候选串口的驱动和 USB 拓扑：

```bash
udevadm info -q property -n /dev/ttyUSB2
lsof /dev/ttyUSB2
```

其中 `/dev/ttyUSB2` 只是示例。若 `lsof` 显示 ModemManager 或项目守护进程正在占用端口，不要直接抢占，也不要未经评估就停止生产服务。

确认无人占用后，可用 `picocom` 做人工测试：

```bash
picocom -b 115200 /dev/ttyUSB2
```

常见退出键为 `Ctrl+A` 后按 `Ctrl+X`。UART 模块还必须按硬件设计确认波特率、数据位、停止位、校验和硬件流控；USB 虚拟串口显示的波特率经常只是兼容参数。

### 3.2 Windows

1. 在“设备管理器 → 端口（COM 和 LPT）”中确认模块端口名称与 COM 号；
2. 用串口工具打开正确端口，常见参数是 `115200, 8N1`；
3. 发送结尾选择 `CR`，必要时选择 `CR+LF`，但不要只发 `LF`；
4. 若端口无法打开，先检查是否被项目程序、厂商工具或另一个串口终端占用。

### 3.3 第一次握手

按顺序发送：

```text
AT
ATE0
AT+CMEE=2
ATI
```

预期每条命令最终都返回 `OK`。若 `AT` 无响应，优先检查：

- 选错端口；
- 模块仍在启动或反复重启；
- 串口参数/流控不匹配；
- 行结束符错误；
- 端口被其他进程占用；
- 电源跌落、USB 线缆或驱动异常。

## 4. 必须掌握的通用指令

下表以 3GPP 通用命令为主。实现是可选的，某条指令返回 `ERROR` 也可能只是该固件不支持。

### 4.1 模块身份与基本状态

| 指令 | 作用 | 备注 |
|---|---|---|
| `AT` | 测试 AT 通道 | 只证明控制口可用 |
| `ATI` | 查询综合身份信息 | 输出格式由厂商决定 |
| `AT+GMI` | 厂商 | 建立设备档案 |
| `AT+GMM` | 型号 | 必须精确到硬件变体 |
| `AT+GMR` | 固件版本 | AT 行为经常随固件改变 |
| `AT+GSN` | 设备序列号/IMEI | 日志对外分享前应脱敏 |
| `AT+CLAC` | 列举支持的 AT 指令 | 可能输出很多，且并非所有固件支持 |
| `AT+CFUN?` | 查询功能级别 | 常见 `1` 表示完整功能，但以手册为准 |

`AT+CFUN=0`、`AT+CFUN=1` 会改变射频/协议栈状态，可能中断所有蜂窝业务；只能放在已批准的恢复流程中。带重启参数的写法兼容性更差，必须查型号手册。

### 4.2 SIM 状态

| 指令 | 作用 | 典型结果 |
|---|---|---|
| `AT+CPIN?` | SIM 是否可用 | `READY`、`SIM PIN`、`SIM PUK`、未插卡等 |
| `AT+CCID` | 查询 ICCID | 部分厂商使用 `AT+ICCID` |
| `AT+CIMI` | 查询 IMSI | 属于敏感用户标识，应脱敏保存 |

只有 `+CPIN: READY` 才能继续正常注册。不要在自动脚本中反复尝试 PIN/PUK；错误次数过多可能锁卡。

### 4.3 运营商与注册状态

| 指令 | 网络域 | 维护意义 |
|---|---|---|
| `AT+COPS?` | 当前运营商与接入技术 | 确认实际选择了哪个 PLMN |
| `AT+CREG?` | 传统电路域 | 主要用于旧网络/语音兼容场景 |
| `AT+CGREG?` | GPRS 分组域 | 主要用于 2G/3G |
| `AT+CEREG?` | EPS/LTE 注册 | LTE 与 5G NSA 诊断非常重要 |
| `AT+C5GREG?` | 5GS/NR 注册 | 5G SA 重点；实现为可选 |

注册状态 `<stat>` 最常见的值：

| 值 | 含义 | 判断 |
|---:|---|---|
| 0 | 未注册，当前也未搜索 | 检查射频功能、选网策略和 SIM |
| 1 | 已注册到归属网 | 注册层正常 |
| 2 | 未注册，正在搜索/尝试注册 | 短时正常；长期存在需查信号、天线、频段、运营商 |
| 3 | 注册被拒绝 | 重点保存拒绝原因，检查卡、套餐、漫游和运营商侧 |
| 4 | 状态未知 | 联合模块日志和小区信息判断 |
| 5 | 已注册，漫游 | 注册成功，但要确认项目是否允许漫游及其费用 |

标准还定义了其他状态值，具体范围会随命令版本和模块实现变化，解析器不能只接受 0～5。

要接收注册变化 URC，可先查询能力再设置：

```text
AT+CEREG=?
AT+CEREG=2
AT+C5GREG=?
AT+C5GREG=2
```

若支持模式 `3`，它通常还能带上注册拒绝原因，适合故障分析。生产程序应先读手册并做能力探测，不要假设所有固件都支持相同的 `<n>`。

> 谨慎：`AT+COPS=?` 会发起全网扫描，可能持续数分钟并影响当前注册。它不是常规健康检查指令。

### 4.4 信号质量

```text
AT+CSQ
AT+CESQ
```

`AT+CSQ` 常见响应是 `+CSQ: <rssi>,<ber>`。当 `<rssi>` 为 0～31 时，传统 RSSI 可粗略换算为：

```text
RSSI(dBm) ≈ -113 + 2 × rssi
```

`99` 表示未知或不可测，不能直接解释成“零信号”。`CSQ` 对 LTE/NR 信息不足，维护 5G 应结合 `CESQ` 和厂商的 serving-cell 指令，重点观察：

- **RSRP**：参考信号接收功率，反映覆盖强弱；
- **RSRQ**：参考信号接收质量，受干扰和负载影响；
- **SINR/SNR**：信号与干扰噪声比；
- **PCI、EARFCN/NR-ARFCN、Band**：当前小区、频点和频段；
- **带宽、LTE 锚点、NR 小区状态**：用于判断 NSA/SA 和吞吐瓶颈。

可用于现场快速判断的经验范围如下。不同频段、天线、模块和业务目标会改变阈值，因此不能把它当成运营商验收标准。

| 指标 | 好 | 一般 | 差 |
|---|---|---|---|
| RSRP | `>= -90 dBm` | `-90 ~ -105 dBm` | `< -105 dBm` |
| RSRQ | `>= -10 dB` | `-10 ~ -15 dB` | `< -15 dB` |
| SINR | `>= 20 dB` | `0 ~ 20 dB` | `< 0 dB` |

不要只看一个瞬时值。至少连续采样一段时间，并结合掉线时刻、吞吐、温度、供电和小区切换记录分析。

## 5. 5G SA、NSA 与“看起来有 5G”

### 5.1 SA

5G SA 直接接入 5G Core。若模块实现标准指令，`AT+C5GREG?` 可观察 5GS 注册状态。但仍需进一步证明 PDU Session、IP 和业务连接正常。

### 5.2 NSA

5G NSA 通常依赖 LTE 锚点：

- LTE/EPS 注册状态由 `CEREG` 反映；
- NR 作为辅链路可能只在有较大数据流量时激活；
- 模块空闲时只显示 LTE，不一定代表 5G 配置失效；
- `C5GREG` 返回不支持或未注册，也不能单独否定 NSA 能力。

因此判断 NSA 至少需要组合证据：LTE 注册、厂商 serving-cell 输出中的 NR 辅小区状态、实际流量期间的 RAT/频段变化，以及数据面吞吐。

### 5.3 四个不能混淆的状态

| 状态 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 搜到小区 | 射频能看到网络 | SIM 已获准注册 |
| 已注册 | 运营商接受终端驻网 | 数据会话已经建立 |
| 已分配 IP | 数据上下文大概率已激活 | 默认路由、DNS、外网正常 |
| 业务请求成功 | 当前端到端链路可用 | 长时间运行一定稳定 |

## 6. APN/DNN、数据上下文与数据面

### 6.1 查询配置和状态

常用只读指令：

```text
AT+CGATT?
AT+CGDCONT?
AT+CGACT?
AT+CGPADDR
AT+CGCONTRDP
```

含义：

- `CGATT?`：分组业务附着状态；
- `CGDCONT?`：已定义的 PDP Context，包括 CID、IP 类型、APN/DNN；
- `CGACT?`：上下文是否激活；
- `CGPADDR`：查询上下文地址；
- `CGCONTRDP`：查询网络下发的动态参数，是否支持取决于固件。

在 5G 模块中，标准接口可能仍使用 `CGDCONT` 的 `<APN>` 参数承载 DNN 配置，以保持兼容。最终应以具体模块的数据业务或拨号应用手册为准。

### 6.2 修改 APN 是业务变更

典型格式：

```text
AT+CGDCONT=1,"IPV4V6","<APN>"
```

这会修改配置，执行前必须确认：

- 运营商提供的准确 APN/DNN；
- CID 是否与拨号程序使用的 CID 一致；
- `IP`、`IPV6` 或 `IPV4V6` 是否符合项目设计；
- 是否需要用户名、密码和认证方式；
- 配置是否持久化、何时生效、回滚方法是什么。

不要照抄公网示例覆盖生产专网 APN。

### 6.3 数据方式决定排障入口

| 数据方式 | 数据如何走 | 常见维护入口 |
|---|---|---|
| PPP | 串口承载 PPP 帧 | `pppd` 日志、PPP 接口、路由、DNS |
| ECM/NCM/RNDIS | 模块呈现 USB 网卡 | 主机网卡、DHCP/静态地址、模块侧会话 |
| QMI | USB 数据口 + QMI 控制口 | 连接管理器、`/dev/cdc-wdm*`、wwan 网卡 |
| MBIM | USB 数据口 + MBIM 控制口 | MBIM 会话、wwan 网卡 |
| 模块内置 socket | 主机用 AT 操作 TCP/UDP/MQTT 等 | 厂商私有 AT 指令、URC、模块内部 DNS/TLS |

不要混用不同拨号体系。例如连接已由 ModemManager/QMI 管理时，再用 AT 私自激活另一个 CID，可能造成配置竞争。

### 6.4 主机数据面验证

Linux 上依次执行以下只读检查：

```bash
ip -br link
ip -br addr
ip route
ip rule
ip route get 1.1.1.1
```

再按项目允许的目标验证：

```bash
ping -c 3 -I wwan0 1.1.1.1
getent hosts example.com
curl --interface wwan0 --connect-timeout 10 https://example.com/
```

`wwan0` 和测试目标都只是示例，应替换为实际接口和经过批准的服务器。

- IP 能通、域名不通：重点检查 DNS；
- 模块已分配 IP、主机没有地址：检查拨号方式和驱动/连接管理器；
- 主机有地址但路由选错：检查默认路由、策略路由和 metric；
- TCP 可达但业务失败：继续检查 TLS、系统时间、证书、代理和应用协议。

## 7. 厂商私有指令怎么学

通用 3GPP 指令只能覆盖基础能力。频段锁定、SA/NSA 偏好、邻区、温度、USB 模式、拨号、GNSS、eSIM、FOTA、模块日志等通常依赖厂商私有指令。

常见前缀只能用于识别风格，不能据此前缀猜指令：

| 厂商 | 常见私有风格示例 | 注意 |
|---|---|---|
| 移远 Quectel | `AT+Q...` | 例如部分 RG/RM 系列支持 `AT+QENG="servingcell"` |
| 广和通 Fibocom | 常见 `AT+GT...` 等 | 不同平台和型号差异明显 |
| 芯讯通 SIMCom | 常见 `AT+C...`、`AT+CN...` 等 | 可能与标准前缀外观相近 |
| Telit Cinterion 等 | `#`、`$` 或厂商扩展 | 以对应手册为准 |

## 8. URC 与生产级解析器

### 8.1 为什么实验脚本容易在生产环境失效

以下写法都不可靠：

- 发送命令后只读一行；
- 看到第一行 `OK` 就结束，但它可能属于其他交互；
- 把所有以 `+` 开头的行都当成命令响应；
- 每次发命令前清空接收缓冲区，导致关键 URC 丢失；
- 多个 goroutine 同时读写同一个 AT 口；
- 所有命令使用相同的 1 秒超时；
- 超时后立刻连续重发，造成模块和网络雪崩。

### 8.2 推荐架构

```text
             ┌───────────────┐
业务请求 ───>│ 命令队列       │
             └──────┬────────┘
                    v
             ┌───────────────┐
             │ 单一串口拥有者 │─── 写命令
             │ 状态机         │<── 连续读字节
             └───┬───────┬───┘
                 │       │
          命令响应流     URC 事件流
                 │       │
              调用方    状态管理/日志/告警
```

解析器应具备：

1. 按字节持续读取，识别 `CR/LF`，同时支持无换行的 `>` 提示符；
2. 识别最终结果码；
3. 按当前命令允许的响应前缀归属中间响应；
4. 把已知 URC 独立投递，未知异步行原样保留；
5. 给每条原始收发记录单调时钟、墙上时间、端口和命令 ID；
6. 对 IMSI、ICCID、IMEI、号码、APN 凭据、短信和定位信息脱敏；
7. 超时后进入重同步状态，确认通道恢复后再执行下一条命令；
8. 对扫描、拨号、FOTA 等慢命令使用独立超时；
9. 对重试设置退避、次数上限和熔断，防止无限复位。

若某条厂商指令进入透传、下载、PPP 或二进制模式，普通逐行解析将不再适用，必须按该模式的退出序列和状态机处理。

## 9. 一份可复制的只读现场快照

在确认 AT 口没有被生产进程占用后，可按下列顺序人工执行。标注“可选”的命令返回 `ERROR` 时，先记录为“不支持”，不要马上把它判断成模块故障。

```text
AT
ATE0
AT+CMEE=2
ATI
AT+GMI
AT+GMM
AT+GMR
AT+GSN
AT+CFUN?
AT+CPIN?
AT+CCID
AT+COPS?
AT+CEREG?
```

## 10. 故障定位决策表

| 现象 | 优先证据 | 常见方向 |
|---|---|---|
| 没有 USB/串口设备 | 供电、USB 枚举、内核日志 | 电源、线缆、硬件复位、驱动、模块崩溃 |
| 有端口但 `AT` 无响应 | 端口用途、占用者、串口参数、原始收发 | 选错端口、流控、模块启动中、端口被占用 |
| `CPIN` 非 READY | `CPIN`、卡座、SIM 状态 | 未插卡、接触不良、PIN/PUK、SIM 故障 |
| 注册长期为 2 | 小区信息、信号、选网/RAT/频段、SIM 套餐 | 弱覆盖、天线、频段不匹配、网络侧暂不可用 |
| 注册为 3 | 拒绝原因、PLMN、IMSI/ICCID 脱敏信息 | 欠费/未开户、漫游限制、非法终端、网络拒绝 |
| 已注册但无 IP | APN/DNN、CID、认证、会话状态 | APN 错、专网权限、PDU/PDP 激活失败 |
| 模块有 IP、主机无网 | 网卡地址、连接管理器、路由、DNS | QMI/MBIM/ECM 流程、DHCP、策略路由 |
| IP 可达、域名失败 | DNS 配置与查询 | DNS 未下发、被覆盖或不可达 |
| 业务偶发断开 | 带时间戳的 URC、USB reset、供电、温度、信号趋势 | 小区切换、电源跌落、过热、驱动/固件异常 |
| 显示 5G 但速度低 | NSA 辅小区、频段/带宽、SINR、测速路径 | NR 未激活、网络负载、回传、套餐限速、主机瓶颈 |

### 10.1 “长期搜索”不要立刻复位

复位会抹掉短暂现场状态，频繁复位还可能让问题更难复现。

## 11. 分级恢复策略

恢复动作应从影响最小到最大，并在每一步后重新验证完整链路：

1. **只读观测**：采集 AT、URC、接口、路由、DNS 和业务探测；
2. **恢复业务会话**：由当前连接管理器重新拨号/重建 PDU 或 PDP；
3. **恢复协议栈**：经批准后执行模块功能级切换，例如 `CFUN` 流程；
4. **模块软件重启**：使用该型号明确支持的命令；
5. **硬件复位或断电重启**：最后手段，必须遵守硬件时序。

每一级都要具备：

- 触发条件，避免把服务器故障误判成模块故障；
- 冷却时间和最大尝试次数；
- 并发互斥，避免多个线程同时恢复；
- 操作前后的证据快照；
- 成功判据：注册 + 会话/IP + 路由/DNS + 项目业务探测；
- 失败后的上报和停止条件。

不建议自动化执行以下高风险操作：全网扫描、锁频段/锁小区、修改 USB 组合、修改 APN、恢复出厂设置、清除 NV、升级固件、反复 PIN/PUK、无上限复位。

## 12. 可选业务：短信和语音

如果项目使用短信，应另外学习 3GPP TS 27.005。常见入口：

```text
AT+CMGF?
AT+CPMS?
AT+CNMI?
AT+CMGL=...
AT+CMGR=...
```

`CMGS` 会发送短信，`CMGD` 会删除短信，属于修改操作。短信正文可能包含验证码和个人信息，日志必须脱敏。

如果项目使用语音/VoLTE/VoNR，仅有 `ATD`、`ATA`、`ATH`、`CLCC` 等呼叫指令还不够；还必须确认 IMS 注册、运营商开通、音频通道和厂商语音配置。不要把“5G 数据已注册”等同于“VoNR 一定可用”。
