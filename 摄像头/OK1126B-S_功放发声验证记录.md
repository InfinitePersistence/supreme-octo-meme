## 5. 源码定位：`Power Amplifier` 的真实语义

**用途**：确认该控件是否就是外接功放的硬件使能，以及空闲 Off 是否正常。

**命令（主机侧）**
```bash
grep -rn "Power Amplifier" kernel-6.1/sound/soc/codecs
grep -rn "pa_ctl"          kernel-6.1/sound/soc/codecs/rk_dsm.c
grep -rn "ctl-gpios"       kernel-6.1/arch/arm64/boot/dts/rockchip/OK1126B-S-common.dtsi
```

**结果（串口现象 → 此处为源码证据）**
- `rk_dsm.c:235` `SOC_ENUM_EXT("Power Amplifier", pa_enum, rk_dsm_dac_pa_get, rk_dsm_dac_pa_put)`
  → get/put 直接操作 GPIO：`gpiod_get_value(rd->pa_ctl)` / `gpiod_set_value(rd->pa_ctl, ...)`
- `rk_dsm.c:471` **`rk_dsm_pcm_startup()` 里自动 `gpiod_set_value(rd->pa_ctl, 1)`**
- `rk_dsm.c:498` `rk_dsm_pcm_shutdown()` 里自动写回 0
- `OK1126B-S-common.dtsi:269` `pa-ctl-gpios = <&gpio7 RK_PA2 GPIO_ACTIVE_HIGH>`
- `rk_dsm.c:554` 停止时写 `DACVOLL0/R0 = RKDSM_VOL_VAL_MAX (0xFF)` + `DACVOGP=NEG` → **反相静音（防爆音）**

**判定**
1. `Power Amplifier` 就是 `GPIO7_A2` 功放使能，**空闲时 Off 是正常设计**，播放开始时驱动自动拉高，无需手动开。
2. 空闲读到 `DAC Digital Volume = 0` 是**假象**：驱动 stop 时把寄存器刷成 `0xFF+NEG`(≈-95.6 dB)，与用户音量无关。

**下一步检测**：造测试音并实际播放，同时观察 gpio 是否被拉高。

## 10. regmap / debugfs 寄存器验证（决定性证据）

**用途**：直接看 DSM codec 硬件寄存器，确认 DAC / DSM / I2S 是否真的被使能。

**命令**
```sh
# 空闲
cat /sys/kernel/debug/regmap/209a0000.acdcdig-dsm/registers

# 播放中
aplay -D hw:0,0 /tmp/t20.wav >/tmp/pl.log 2>&1 &
sleep 2
cat /sys/kernel/debug/regmap/209a0000.acdcdig-dsm/registers > /tmp/reg_play.txt

# 【对照实验】验证 dump 是否为实时值：改 HPF Cutoff 后重 dump
amixer -c 0 cset numid=43 3        # DAC HPF Cutoff -> 140Hz
cat /sys/kernel/debug/regmap/209a0000.acdcdig-dsm/registers > /tmp/reg_hpf.txt
diff /tmp/reg_play.txt /tmp/reg_hpf.txt
```

**结果（串口现象）**

对照实验证明 dump 是实时的：`0a8` 由 `00000000` → `00000030`（140Hz = 0x3<<4）。

**播放中**：
```
008 DACDIGEN     = 00000011   bit0 DACEN_L0R1 + bit4 DAC_GLBEN  -> DAC 使能
028 DACDSM_CTRL  = 00000058   bit3 DSM_EN + bit4 MODE0 + bit6 CKE -> DSM 调制器工作
050 DACVOLL0     = 00000000   } 0x00 + DACVOGP=NEG -> 0 dB 单位增益
060 DACVOLR0     = 00000000   }
070 DACVOGP      = 00000000   NEG
048 DACMUTE      = 00000000   未静音
11c I2S_XFER     = 00000002   RXS_START -> 正在接收 I2S 数据
```

**停止后**：
```
008 = 00000000  (DAC 关)   028 = 00000010  (DSM 关)
050 = 000000ff  (-95.6dB 反相静音，防爆音)   11c = 00000000  (I2S 停)
```

**判定**：播放时 SAI2→DSM 的 I2S 在收、DAC 开、DSM 调制器开、音量为 0 dB 且未静音；停止后按防爆音流程干净关门。**SoC 侧 100% 正常。**

**下一步检测**：确认 DSM 输出引脚是否真的复用到 AUD_RN/AUD_RP。

# 附录 B：三个容易误判的坑（务必注意）

1. **空闲时 `amixer` 读 `DAC Digital Volume` 永远是 `0`，这是假象。**
   驱动在 stop 时主动写入 `0xFF + NEG`（≈-95.6 dB）做反相防爆音（`rk_dsm.c:554`）。
   播放开始时才用缓存值恢复。**不要把它当作"音量被静音了"去排查。**
   已保存的用户音量在 `/var/lib/alsa/asound.state` 中为 `value.0/1 = 255`（= 0 dB）。

2. **`Power Amplifier` 空闲显示 `Off` 也是正常的。**
   `rk_dsm_pcm_startup()`（`rk_dsm.c:471`）在每次播放开始时自动 `gpiod_set_value(pa_ctl, 1)`，
   停止时自动拉低，**无需任何 amixer 干预**。想强制常开才需要 `amixer -c 0 cset numid=45 1`。

3. **本板当前固件只有一条播放输出通路：DSM 喇叭通路。**
   编译产物 `.OK1126B-S-linux.dtb.dts.tmp` 中：
   - `acodec-sound`：`rockchip,codec = <&audio_codec_pmu>, <&acdcdig_dsm>`（**没有** `audio_codec`）
   - `audio-codec@20bf0000`（主模拟 codec，管耳机/LINE OUT）：**`status = "disabled"`**

   → 接耳机口 / LINE OUT **不会响**；要支持必须改 DTS 打开主 codec 并加入 sound 节点。

4. **声学回采（麦克风）不能作为判据。** 本次寄存器已证明在输出，但板载 mic 完全没采到 1 kHz。
   判定发声请用：**寄存器 + `pa-ctl` gpio 状态 + 实听**。
