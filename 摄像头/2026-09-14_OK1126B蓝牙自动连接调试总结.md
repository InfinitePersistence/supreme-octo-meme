# OK1126B（RV1126B）蓝牙自动连接调试总结

- 调试日期：2026-09-14
- 平台：OK1126B / RV1126B，Buildroot 2024.02，BlueZ 5.77，BlueALSA 4.1.1
- 蓝牙控制器：hci0，58:E4:EB:88:82:CF
- 测试手机：小米

## 1. 问题

开发板重启后，小米手机保留了 OK1126B 的配对记录，但无法作为蓝牙音箱稳定连接。

此前的判断“配对密钥或信任记录丢失”不成立。SSH 现场读取确认手机记录仍在：

```text
Paired: yes
Bonded: yes
Trusted: yes
Blocked: no
```

实际根因有两项：

1. BlueALSA 二进制已安装，但没有 `bluealsa.service`，重启后没有运行 `bluealsa -p a2dp-sink`；开发板未注册 A2DP Sink endpoint。
2. `bt-agent.sh` 通过无限循环向 `bluetoothctl` 输入 `yes`。没有授权请求时，这些输入落在主菜单，持续产生 `Invalid command in menu main: yes`，属于时序脆弱的脚本缺陷。

## 2. 现象与证据

### 2.1 手机配对记录正常

```text
Device 88:6C:60:6D:9A:C2
  Paired: yes
  Bonded: yes
  Trusted: yes
  Blocked: no
  Connected: no
```

因此无需删除手机配对记录或重新配对。

### 2.2 缺少 A2DP Sink 服务

```text
systemctl status bluealsa
Unit bluealsa.service could not be found.

pgrep -x bluealsa
# 无输出
```

虽然 `/usr/bin/bluealsa` 存在并支持 `a2dp-sink`，但未运行时 BlueZ 没有可用媒体端点，手机无法建立蓝牙音箱音频链路。

### 2.3 Agent 无条件输入

旧脚本不断写入 `yes`：

```text
[bluetooth]# yes
Invalid command in menu main: yes
```

该行为原本试图处理 `Authorize service`，但不能可靠识别授权提示，且会污染日志。

## 3. 解决方法（附代码）

### 3.1 新增 BlueALSA A2DP Sink systemd 单元

文件：`/etc/systemd/system/bluealsa.service`

```ini
[Unit]
Description=BlueALSA A2DP sink for OK1126B
After=bluetooth.service
Requires=bluetooth.service

[Service]
Type=simple
ExecStart=/usr/bin/bluealsa -p a2dp-sink
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
```

执行：

```sh
systemctl daemon-reload
systemctl enable bluealsa.service
systemctl start bluealsa.service
```

### 3.2 修复 Just Works Agent

文件：`/usr/bin/bt-agent.sh`

```sh
#!/bin/sh
# OK1126B Bluetooth pairing agent: Just Works, without unconditional replies.
set -eu

log=/tmp/bt-agent.log
: > "$log"

until bluetoothctl show >/dev/null 2>&1; do
    sleep 1
done

(
    sleep 1
    printf '%s\n' 'agent off'
    sleep 2
    printf '%s\n' 'agent NoInputNoOutput'
    sleep 2
    printf '%s\n' 'default-agent'
    while :; do
        sleep 3600
    done
) | exec bluetoothctl > "$log" 2>&1
```

对应单元：`/etc/systemd/system/bt-agent.service`

```ini
[Unit]
Description=BlueZ Just Works pairing agent
After=bluetooth.service
Requires=bluetooth.service

[Service]
Type=simple
ExecStart=/usr/bin/bt-agent.sh
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
```

说明：

- `NoInputNoOutput` 负责 Just Works 配对。
- 已信任设备访问 A2DP 不需要无条件 `yes`。
- 此 Agent 不等于量产级未知设备授权策略；后续若需要任意新手机自动受信任，应改为原生 BlueZ D-Bus Agent。

### 3.3 备份与回滚位置

本次修改前的文件已备份，备份名称包含缺陷名称：

```text
/root/bt-backups/20260914-a2dp-sink-service-missing-unconditional-yes-agent-defect/
├── bluealsa.service.a2dp-sink-service-missing.before-repair.absent
├── bt-agent.service.unconditional-yes-agent-defect.before-repair

```

## 4. 解决后现象

已验证：

```text
systemctl is-active bluealsa bt-agent
active
active

pgrep -a -x bluealsa
/usr/bin/bluealsa -p a2dp-sink
```

BlueALSA 已在 D-Bus 上注册 `org.bluealsa`，并向 BlueZ 注册两个 SBC A2DP Sink endpoint：

```text
Endpoint registered: /org/bluez/hci0/A2DP/SBC/sink/1
Endpoint registered: /org/bluez/hci0/A2DP/SBC/sink/2
```

控制器随后出现：

```text
UUIDs: 0000110b-0000-1000-8000-00805f9b34fb
```

`0x110B` 是 Audio Sink。此前记录把 `0x110D` 标为 Audio Sink 不准确；`0x110D` 是 Advanced Audio Distribution profile UUID。

Agent 已成功注册 NoInputNoOutput，且新日志中不再出现 `Invalid command in menu main: yes`。

未完成的端到端验证：

- 板端执行 `bluetoothctl connect 88:6C:60:6D:9A:C2` 返回该设备对象未提供 `Device1.Connect`，不能作为手机主动连接音箱的替代测试。
- 仍应从手机蓝牙设置点击 OK1126B 并播放音频，确认 `Connected: yes` 与 BlueALSA transport 建立。

## 5. 下一步

### 开发板实用方案

若需要“长按实体按键开启配对、自动信任、最多 8 台、单手机音频”，可新增策略服务：

1. 监听 `/dev/input/event1`（`bt-powerkey`），长按 3 秒开启 120 秒配对窗口。
2. 正常模式强制 `Discoverable=false`、`Pairable=false`；配对窗口结束后自动关闭。
3. 配对前以 `bluetoothctl devices Paired` 计数；达到 8 台时拒绝开启窗口。
4. 新设备 `Paired=yes` 后执行 `bluetoothctl trust <MAC>`，并立即结束当前窗口。
5. 轮询已配对设备的 `Connected` 状态，仅保留第一台活动手机，断开后来连接的设备。
6. 仅保留 BlueALSA A2DP Sink；当前控制器仍显示 PBAP、OBEX、MAP 等 profile，必须在启用前逐项验证 Bluetoothd 插件白名单。

该脚本方案适合开发板验证，但首次配对到自动 Trust 存在秒级竞态。严格产品化需改为原生 D-Bus Agent，在 `RequestAuthorization`、`RequestConfirmation`、`AuthorizeService` 回调中执行策略。

### OTA

当前开发板为单 rootfs 分区，没有 A/B 系统槽位和 OTA 工具。可先将未来策略脚本、版本清单、备份和回滚脚本保存在 `/userdata/bt-product/`，实现蓝牙配置级回滚；这不等于整机镜像 OTA 回滚。
