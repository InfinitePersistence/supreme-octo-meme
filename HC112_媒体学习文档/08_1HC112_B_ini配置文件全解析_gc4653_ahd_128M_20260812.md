### 文件名后缀怎么读（先看这一节，再进具体文件）

以 `config_product_mediamode_cam0_record_1440p30_wdr.ini` 为例：

```text
config_product_mediamode_cam0_record_1440p30_wdr.ini
│      │       │         │    │      │       └─ wdr：宽动态版本
│      │       │         │    │      └──────── 1440p30：历史档位名/基础采集档名
│      │       │         │    └─────────────── record：录像用途

│      │       └────────────────────────────── mediamode：媒体模式参数

```

> **判断实际工作参数的优先级：文件内字段 > `config_cfgaccess_entry.ini` 映射 > 文件名后缀。** 这些文件名包含历史命名，不能只看名字判断最终输出。例如 `cam0_record_1440p30.ini` 当前是 GC4653 2560×1440、19 fps 采集，经 VPSS 放大到 3840×2160，再由 VENC 做 19→25 插帧；`cam0_record_2160p30.ini` 当前实际按 4K25 使用；`cam1_record_1080p30.ini` 当前实际为后路 1080P25。

| 后缀或片段 | 表示什么 | 发生错误时优先看什么 |
|---|---|---|
| `cfgaccess_entry` | 所有逻辑模块的入口索引 | 配置完全没生效、加载错文件：看 `moduleN`、节名、`path`、`cfg_filename` |
| `devmng` | 设备级默认值与能力 | 型号/版本/WiFi/GPS/停车/按键/声控异常：看对应功能节及 `valueset` |
| `filemng` | 文件目录、空间配额、修复策略 | 卡满删文件异常、目录不对、格式化后录像异常：看 `dtcf`、目录名、比例和阈值 |
| `mediamode_common` | 所有媒体档共用的编码、音频、显示参数 | 所有分辨率都出现同一种编码或音频问题：先看这里 |
| `cam0` / `cam1` | 前摄 / 后摄 | 先确认问题属于哪一路，再沿该路的 VI→VPSS→VENC→REC 句柄排查 |

| `comm_record` | 录像链路的公共 VI/VPSS/VENC 拓扑 | 能预览但不能录像、句柄绑定错误：看 `vcapdevhdl`、pipe、vpss、vport、venc |
| `comm_photo` | 拍照链路的公共拓扑 | 能录像但不能拍照、JPEG/缩略图错误：看拍照 pipe、vport、JPEG VENC 句柄 |
| `record` | 录像媒体档 | 分辨率、帧率、码率、GOP、VB 池、插帧异常：看本档的 `[vb]`、`[vcap]`、`[vpss]`、`[venc]` |

| `1080p` / `1440p` / `2160p` | 历史分辨率档名 | 最终分辨率以 `vpss.vport res_*` 和 `venc res_*` 为准，Sensor 输入以 `sensor_*` 为准 |
| `p30` | 历史目标帧率档名 | 实际帧率必须同时核对 VI、ISP、VPSS、VENC 的 `src_framerate/dst_framerate` |

### 媒体元素和句柄分配速查

排查时不要只看某一个数值，应沿着数据链逐段核对：

```text
Sensor/AHD
  → VI device（vcapdevhdl）
  → VI pipe（vcappipehdl）
  → pipe channel（pipechnhdl）
  → VPSS group（vpsshdl）
  → VPSS port（vporthdl）
  → VENC（venchdl）
  → REC task（normal.0/normal.1 中的 venc_hdl0）
  → 文件目录（Front_Norm/Back_Norm、Front_Emr/Back_Emr）
```

| 资源 | 前路 cam0 | 后路 cam1 | 对不上时常见表现 |
|---|---|---|---|
| VI device | `vcapdevhdl=0` | 录像常用 `vcapdevhdl=1`；拍照配置另有设备号 | Sensor/AHD 初始化失败、无帧、绑定失败 |
| VI pipe | 主录像 `vcappipehdl=0` | 后路录像公共配置绑定 pipe 1；后路拍照媒体档另有 pipe 4/5 | `GetFrame` 超时、起流失败、取错摄像头 |
| pipe channel | 通常 `pipechnhdl=0` | 通常 `pipechnhdl=0` | VI 有输入但 VPSS 收不到帧 |
| VPSS group | `vpsshdl=0` | `vpsshdl=1` | 前后路串画面、缩放/镜像作用到错误摄像头 |
| VPSS port 0 | 前路主录像/主拍照源 | 后路主录像/主拍照源 | 主录像黑屏、分辨率不对 |
| VPSS port 1 | 前路次码流/App预览相关 | 后路次输出/快照相关，按具体公共文件确认 | App 预览黑屏、次码流错误 |
| 前路 VENC | 主录像 `0`；主快照 `1`；缩略/次快照按公共配置看 `2/5` | — | 前录无文件、编码器重复创建、OSD绑错 |
| 后路 VENC | — | 主录像 `3`；快照常见 `4/6/7`，必须结合当前工作模式确认 | 后录无文件、照片写错路、VENC 已存在 |
| REC task | `normal.0`，应引用前路主 VENC `0` | `normal.1`，应引用后路主 VENC `3` | 编码有数据但不生成文件，或前后路文件内容错位 |
| OSD batch | cam0 通常十位为 `0` | cam1 通常十位为 `1`（如 `10+type`） | 水印跑到另一摄像头、开关控制错对象 |

> 上表是当前目录的常用录像链路。拍照模式、WDR、缩时媒体重建时可能切换 pipe 或 JPEG VENC，最终以当前加载的 `comm_*`、媒体档和 `workmode_*` 三层配置共同结果为准。

| 有预览但录像不生成文件 | `workmode_record.ini` | `normal.N enable`、`venc_hdl0`、`venccnt`、muxer、目录、SD状态 | REC任务引用错VENC，录像任务未启用，文件系统不可写 |

| USB UVC/读卡异常 | `workmode_usb.ini` | `usb_mode`、capability、datasource、buffer、`dev_path/sysfile` | 模式值、视频源、缓冲或USB gadget节点不匹配 |

### 内存与缓冲怎么估算

- **YUV420 单帧原始大小**约为 `宽 × 高 × 3 / 2`；YUV422 约为 `宽 × 高 × 2`。`vb.pool.N.blk_size` 不能小于真实帧及对齐后的需求。
- **VB池占用**约为 `Σ(blk_size × blk_count)`，还应预留驱动、ISP、VPSS和对齐开销；不能把所有 MMZ 都分给配置中的可见池。
- **录像RingBuf需求**可先按 `码率(kbps) ÷ 8 × recbuffer_time(ms) ÷ 1000` 估算字节，再考虑 I 帧峰值、音频、索引及安全余量。前后路需求需要相加。
- **VENC `bufsize`**是编码通道缓冲，不等于录像 `recbuffer_time` 对应的RingBuf；两者都会占用内存，不能只扩大其中一项。
- **`recvbuf_size`**是录像接收侧缓冲，不能替代VB、VENC或RingBuf。遇到无内存问题时，要把四类占用分开核算。

### 修改后必须闭环核对

1. 在 `config_cfgaccess_entry.ini` 确认实际加载的是目标文件。
2. 在 `workmode_record/photo/usb.ini` 确认当前工作模式选中了目标 `mediamode`。
3. 从 Sensor/VI 开始，逐级核对 pipe、channel、VPSS group、vport、VENC 和 REC task 句柄。
4. 核对每级分辨率和帧率，不能只修改 VENC 最后一层。
5. 重新计算 VB、VENC、RingBuf 和 MMZ 总量，并检查前后路同时开启的峰值。
6. 对照启动日志确认实际创建的句柄、分辨率、帧率和缓冲大小，而不是仅凭 INI 文件名判断。

## 1. 通用字段字典（每个媒体模式文件都有的公共字段，先记熟）

### [common] 公共
| 字段 | 含义 |
|---|---|
| `mediamode` | 该文件对应的媒体模式枚举（如 `OT_PARAM_MEDIAMODE_1440P_30`），App 里档位识别用 |
| `[common.vcap.pipe.N]` `vivpssmode` | VI/VPSS 工作模式：0=vi离线,vpss离线；1=vi离线,vpss在线；2=vi在线,vpss离线；3=都在线；4=vi并行,vpss离线；5=并行；6=butt |
| `vcappipe_hdl` | 对应的 VI pipe 句柄号 |

### [vb] 视频缓冲（VB 池）
| 字段 | 含义 |
|---|---|
| `max_poolcnt` | VB 池数量（本目录 128M 内存，池数 1~6 不等） |
| `[vb.pool.N]` `blk_size` | 每个缓冲块大小（字节），注释里常标 `宽*高*3/2`（YUV420 一帧） |
| `blk_count` | 该池缓冲块数量（≥ 帧数需求，越多越抗抖动但费内存） |

### [vcap.dev] 视频采集设备（sensor）
| 字段 | 含义 |
|---|---|
| `sensor_type` | sensor 型号枚举（30=gc4653；20=AHD 后路） |
| `sensor_mode` | sensor 工作模式（0=普通，1=WDR/多曝光相关） |
| `sensor_width/height` | sensor 实际输出分辨率（GC4653=2560x1440） |
| `bas_width/height` | 基础分辨率（一般=sensor 分辨率） |
| `wdr_mode` | 宽动态模式：0=none；1=内置；2=quadra line；3=2_1 line；4=2_1 frame |
| `cacheLine` | ISP 缓存行数（建议 height/2） |
| `data_type` | 输入数据类型：0=RAW8；1=RAW10；2=RAW12；...；8=BUTT |
| `componentmask0/1` | 多路数据分量掩码（WDR 双帧用） |

### [vcap.pipe.N] VI 通道
| 字段 | 含义 |
|---|---|
| `enable` | 该 pipe 是否使能 |
| `src_framerate/dst_framerate` | 输入帧率/输出帧率（**本方案前路 19fps 采集就体现在这**） |
| `isp_bypass` | 是否旁路 ISP（1=不经过 ISP，AHD 后路用） |
| `isp_framerate` | ISP 帧率 |
| `isp_width/height` | ISP 处理分辨率 |
| `frameinterrupt_type` | 帧中断类型：0=start；1=early；2=early_end |
| `earlyline` | 提前中断行号（与 frameinterrupt_type 配合） |
| `scene_param_idx` | 场景参数索引（WDR 或不同场景） |
| `isp_mirrorflip` | ISP 级镜像翻转（0=正常） |
| `[vcap.pipe.N.chl.M]` `dst_width/height` | 该 pipe 通道输出分辨率 |

### [vpss.N] 视频处理器
| 字段 | 含义 |
|---|---|
| `max_width/height` | VPSS 最大处理分辨率 |
| `crop_start_x/y`、`crop_width/height` | 裁剪窗口（放大 4K 时 crop 用的就是 2560x1440 区域） |
| `[vpss.N.vport.M]` `res_width/height` | **vport 输出分辨率**（前路 vport0 放大到 3840x2160 就在这） |
| `src/dst_framerate` | vport 输入/输出帧率 |

### [venc.N] 视频编码器
| 字段 | 含义 |
|---|---|
| `res_width/height` | 编码分辨率 |
| `bufsize` | 码流缓冲大小（字节） |
| `gop` | GOP 长度（I 帧间隔，与帧率相关） |
| `src_framerate` | 编码输入帧率（实际喂给编码器的帧率） |
| `dst_framerate` | 编码输出帧率（**前路 25=插帧目标，19→25 就体现在这**） |
| `h265bitrate/h264bitrate` | H265/H264 码率（kbps） |
| `stat_time` | 码率统计时间（秒） |
| `payload` | 编码格式：0=h264；1=h265；2=MJPEG；3=JPEG；4=AAC |
| `rcmode` | 码控模式：0=cbr；1=vbr；2=qvbr |
| `type` | 0=main video；1=sub video；2=single snap；3=sub snap |

## 27. 复习要点

1. **入口**：`config_cfgaccess_entry.ini` 把 24 个逻辑模块映射到具体 ini 文件，改配置先看它。
2. **三大公共**：`mediamode_common`（编码器 QP/音频）、`cam0_comm*`（通道绑定）、`workmode_*`（录像/拍照/OSD）。
3. **媒体档**：`cam0_record_*` 是 6 个前摄录像档，结构都是 `common→vb→vcap→vpss→venc`，差异在 分辨率/帧率/WDR/插帧。
4. **插帧档**：`1440p30.ini` 的 `src=19/dst=25` 触发插帧（配合 `MEDIA_IsVencFrameInsertionAttr`）。
5. **WDR 档**：`*_wdr.ini` 用 `wdr_mode=3` + 双 pipe（pipe0/1 都 enable）+ `sensor_mode=1`。
6. **选项集**：`valueset.ini` 是所有 App 下拉菜单的数据源，改可选项在这里。
7. **版本差异**：`devmng.ini` 里 `otainfozx/otainfos22/otainfoultra_1` 三个版本节点，编译时选一套。
8. **OSD**：`workmode_record.ini` 里 osd.0~8 分别绑到前/后摄主次码流（时间/GPS/logo）。
9. **AHD 后路**：`cam1_*` 用 `isp_bypass=1` + YUV 输入，不经过 ISP。
